## 数据库使用边界

- `database/schema.sql`：当前 48 张表的结构，不包含业务数据。仅用于新建的空数据库。
- `database/seed.sql`：基础菜单、角色、字典、系统配置及虚构演示账号。只在空库导入表结构后执行，不得覆盖现有数据库。演示账号为 `admin`、`teacher_demo`，密码均为 `123456`，仅供本机测试。
- `database/migrations/20261004_material_shop.sql`：已有旧版数据库的资料商城迁移脚本。执行前备份，先核对结构和历史订单；涉及关闭历史未支付订单时，须人工审核并按脚本提示批准。新建库导入当前表结构后，不再执行该迁移。
- `database/Dump20260924.sql`：仅四张历史表的结构，用于迁移自动化测试，不包含原始行数据，也不是业务数据库备份。

资料商城复用 `sys_user`、`sys_role`、`sys_user_role` 和现有权限体系，不另建商城用户表或角色表；扩展 `edu_material`、`edu_material_order`，增加商品图片、订单明细、支付记录、发货记录、订单日志、收货地址及迁移记录表。

本次新增的数据库脚本不包含真实学生、教师、收货地址、电话、订单或支付数据。协作仓库原有的表格、旧 SQL、压缩包和历史提交未在本次上传中全面审计，不能因为有脱敏初始化脚本就认为整个仓库历史均已脱敏。

## 安全边界

- `TOKEN_SECRET` 必须通过环境变量设置；数据库账号、密码使用 `MYSQL_USER`、`MYSQL_PASSWORD`，正式微信配置使用 `WECHAT_APPID`、`WECHAT_SECRET`。不要把真实密钥或密码提交到仓库。
- 默认关闭模拟微信登录。仅使用 `--spring.profiles.active=druid,local` 在本机演示时，启用模拟角色登录和模拟支付；不允许在生产环境启用 `local`。开发工具 AppID 为占位测试号，需要替换成有开发权限的 AppID。
- 当前支付只模拟流程，不会实际扣款；未实现真实微信支付的生产接入。演示密码必须在对外部署前更改，不能直接上线使用演示数据库。
- 本机后端默认 `8080`、Redis 默认 `127.0.0.1:6379`；开发工具中的 `127.0.0.1` 仅指本机，真机调试需要可达地址。对外部署还需 HTTPS、合法域名、独立最小权限数据库账号及正式支付实现。
- 数据库自动化测试会重建专用库 `codex_material_shop_test_20261004`，不得在该库保存业务数据。本次上传不提交依赖、构建产物、上传文件或内部开发 `.md` 文档。

## 本地教师登录与协作同步

- 本地模拟教师登录不再依赖固定的 `teacher_demo`。使用 `druid,local` 配置启动后，若未指定账号，会复用数据库中用户编号最小的正常、未删除且具有启用教师角色的账号；此选择固定可重复，不新增用户、角色或表。
- 需要调试某位教师的数据时，在本机启动环境中设置 `WECHAT_MOCK_TEACHER_USERNAME` 为该教师已有用户名；也支持 `WECHAT_MOCK_TEACHER_PHONE`。用户名优先，配置错误、账号停用或缺少教师角色时明确报错，不自动切换成其他人。手机号只匹配可用教师，多个教师共用该手机号时须改用用户名。修改环境变量后需重启后端。不要把真实用户名或手机号写入共享配置提交 GitHub。
- 这些选项仅用于本地模拟模式；正式微信登录默认关闭模拟功能，必须配置真实微信凭据，不能依赖前端选择身份获得教师权限。
- 本次登录修复无数据库结构变更，无须导入任何 SQL。已有数据库不得重新导入 `schema.sql` 或 `seed.sql` 来解决缺少演示账号的问题。
- Git 只同步代码与 SQL 脚本，不会自动同步 MySQL 数据。后续涉及数据库变更时，代码和对应增量脚本一并提交到 `database/migrations/`；拉取后先备份，核对并执行尚未执行过的脚本，再打包启动。迁移须保留已有数据并考虑重复执行，真实用户、电话、地址、订单及密钥不进入提交。
- `database/schema.sql` 是资料商城发布时的 48 表快照，不包含之后合入的作业表。已有库不要直接运行含 `DROP TABLE` 的 `RuoYi-Vue-master/sql/edu_homework.sql`；作业功能的数据库升级需另行审核、备份并使用保留数据的迁移，不属于本次登录修复。

## 课程收费、收据、退费与优惠券

课程财务继续复用 `edu_enrollment` 作为账单、`sys_user` 家长身份和现有角色／菜单权限；仅新增 `edu_tuition_payment`（收款事实）、`edu_tuition_refund`（退费及审核）、`edu_tuition_receipt`（收据快照）、`edu_coupon_template`（券规则）、`edu_user_coupon`（已有家长持有的券）。资料商城流程不变。

- 已有库：先停后端、私下备份，再执行 `database/migrations/20261007_tuition_finance.sql`，记录文件 SHA256、执行时间和数据库名；核对结构及历史报名后重新打包启动。脚本不删表、不覆盖用户密码、不伪造收费金额；类型冲突或重复有效报名会停止。重复执行不得重置已完成核验的数据。
- 新库：先初始化 `database/schema.sql` 与虚构 `seed.sql`，再执行课程财务增量脚本。48 表基础快照不是包含课程财务／作业功能的最终整库快照，不要把它覆盖到有数据的库。
- 迁移前所有报名显示“历史待核验”，原支付／教学状态保持；金额未知是空值，不是0元。管理员在“收费财务 → 课程收费 → 历史核验”上传证据后核实实际金额和发生时间。普通报名页面不能直接改支付状态、删除缴费历史或绕过退款取消报名。
- 新报名按排课的 `tuition_price` 初始化账单；NULL 为待核价，0为明确免费。财务可针对未付款账单核价，线下收款先登记后核对确认；成功收款才生成收据。真实退款要先申请、由另一名管理员审核、执行并凭到账证据确认；审核通过不代表退款成功。部分退款不会再次产生欠费，退课在退款完成后释放一次名额，保留考勤历史。
- 真实线下渠道为现金、银行转账、线下微信收款；**未接通真正微信在线支付**。本地 `druid,local` 且 `payment.mode=mock` 才能把无支付历史的账单设为MOCK并演示支付／退款，界面和收据均标注模拟；不能将模拟流水作为真实收入。生产配置拒绝模拟操作。
- 收据／凭证保存在 `RUOYI_FINANCE_PRIVATE_PATH` 指定的私有目录，默认是公开上传目录旁的 `*-finance-private`，必须持久化且不能放在 `/profile/` 内。上传校验PDF／PNG／JPEG真实内容、10MB限制、上传者及具体业务。下载仅通过带登录权限的业务接口；临时凭证24小时内绑定，绑定后不依赖Redis存活。
- PDF随应用带 OFL 许可的中文字体，Mac／Windows无需安装字体。生成失败不撤销已确认收款，可在收据管理重试同一号码；作废补开保留旧快照和关联，不改变实收金额。收据是内部收款凭证，不是税务发票。
- 增量脚本包含“收费财务”四个网页菜单和按钮权限；家长小程序新增我的缴费／收据／退费／优惠券，管理员连接收费入口。拉取代码后需执行SQL并重新登录网页以刷新菜单权限，微信工具重新编译。
- 新增自动化测试仅重建专用库 `codex_tuition_finance_test_20261007`，不在该库存业务数据；凭证、数据库备份、生成PDF和本机配置均不应推送GitHub。代码和本次增量SQL需一起合并，已发布脚本后续修正使用新编号。
