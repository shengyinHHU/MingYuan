# 一对一与团队功能整合说明

## 1. 整合范围

2026-10-11，以团队 `main` 的 `ce2e1f8` 为基线，在 `codex/integrate-one-to-one` 整合原功能分支及其未提交修改。原分支、Git stash 和仓库外备份保留，未改写团队历史。

| 业务 | 统一实现 |
| --- | --- |
| 一对一课程与报名 | `edu_course_schedule`、`edu_enrollment` 和 `OneToOneEnrollmentService`；沿用教师发布、确认、取消审批、出勤与完成流程 |
| 教师资料 | `edu_teacher_profile`；学科、教师等级不再读写旧的系统表扩展字段 |
| 孩子身份 | `edu_student`；由孩子管理入口创建，归属于家长，不凭同名推定同一个孩子 |
| 课次余额 | `edu_student_lesson_account` 通过学生编号关联档案；跨学科使用，资深教师双倍额度，报名暂占、完成消耗、取消返还 |
| 课次历史 | `edu_lesson_credit_event` 与 `edu_enrollment_event`，保留发放、收回、暂占、消耗、取消与操作历史 |
| 收费、收据、退款、优惠券 | 团队 `TuitionService`、`CouponService` 及 `edu_tuition_*`；取消重复的直接修改付款状态接口 |
| 个人账户 | 汇总本人孩子、报名、商城订单、课次流水及团队财务流水；现金缴费、退款跳转已有财务页面 |
| WiFi、复核、作业批阅 | 保留团队 PR #9 的入口、页面和服务 |

原来未接入 Controller 的 `system/lesson` 预约服务、规则和对应测试已经移除，避免两套预约、扣次和取消规则并存；代码仍可从 Git 历史查阅。仅保留 `LessonFinance` 财务适配器，校验当前报名和已复核请假考勤，不查询旧预约表、不修改课次余额。原 `database/migrations/20261010_one_to_one.sql` 已标记停用并主动拒绝执行，不能再作为安装脚本使用。

## 2. 权限和状态衔接

1. 教师只能处理本人课程、报名与课次；家长只能管理本人孩子及查看本人账户。开发教师登录必须明确选择教师，不自动登录另一位教师。
2. 家长报名一对一可以选择单次付费或课包。单次付费的教师确认与付款独立；课包不足不得报名。
3. 一对一取消由教师审批，财务接口不能直接取消或返还课次。班课继续使用团队财务的取消保护。
4. 教师取消时，无收款事实的账单可以关闭；已收款、真实在途及结果未知的付款继续保留，由财务处理。取消动作不伪造“已退款”。
5. 一对一退课退款须先完成教师取消或拒绝。收款沿用团队线下登记、确认及收据流程；新退款由家长提交原因，教务核定金额，再由管理员单独登记线下已退款。家长端没有课费在线支付或模拟确认入口。
6. 新报名同时关联孩子编号和课次账户；孩子改名不覆盖旧报名姓名快照。旧记录只有可靠的账户关联才自动补学生编号，其余由管理员核对，禁止按姓名猜测归属。
7. 报名唯一约束同时考虑孩子、具体课次日期和有效状态，避免同名兄弟姐妹或历史连续课次被财务班课索引误拦；一对一单课次席位约束继续保留。

## 3. 增量 SQL 执行顺序

先停止后端，备份整库及结构。逐个执行，遇错即停，不使用 `--force`。不要用整库初始化或历史建表 SQL 覆盖已有数据。

### 3.1 已有本分支的一对一、固定时段和课包表

依次执行仓库 `database/migrations` 下：

1. `20261011_unified_children.sql`：复用团队学生表结构，补学生身份外键，按已有账户逐条建立明确身份关联，保留账户编号与余额。
2. `20261007_tuition_finance.sql`：安装团队财务并采用兼容孩子、日期的有效报名索引；历史账单保持待核验，不补造金额或收款事实。
3. `20261010_tuition_refund_single_admin.sql`：沿用团队开发阶段单管理员审核设置。
4. `20261011_enrollment_identity_compat.sql`：确认替代约束已存在后，移除已被覆盖的旧姓名唯一索引。
5. `20261011_wifi_checkin_compat.sql`：补齐团队 WiFi 白名单和上下班打卡表；不生成白名单、教师或打卡数据。兼容空的旧课次打卡表；若旧表已有无法识别上下班类型的记录，则停止并要求先核对映射。

前四份迁移均已在隔离副本中重复执行验证；WiFi 迁移单独验证首次安装、重复执行、空旧表升级、同日同类型防重复及历史记录保护。已有 WiFi 白名单和上下班打卡表的环境，也可执行第五份做结构检查。

### 3.2 尚未安装本分支的一对一基础表

先审查并按已有结构补齐 `RuoYi-Vue-master/sql` 下的 `20261009_one_to_one_incremental.sql`、`20261011_teacher_profile_incremental.sql`、`20261011_one_to_one_fixed_slots_credits.sql`，再执行 3.1。基础脚本含一次性 ALTER，不能盲目重复执行。

若已经安装另一套 `edu_student_package`、`edu_one_to_one_slot`、`edu_one_to_one_booking` 或 `edu_lesson_unit_log`，身份迁移会停止。须先核对这些表的记录并制定映射，不能删除有记录的表，也不能按姓名自动合并；本次开发库没有这些表。
