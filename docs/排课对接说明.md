# 教师排课对接说明

## 当前范围

教师小程序复用若依排课服务进行增删改查，教师只能为本人新增一对一课程（`classMode=2`），一次固定两小时。管理员可新增班课。现有班课保持原有数据和展示。

星期标题与课程网格在同一个横向滚动容器内，左侧时间轴固定。周课表按实际日期、起止时间和调课记录展开；日期或重复规则缺失时显示待排。

## 教师小程序接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/miniapp/teacher/course/schedules` | 本人排课及调课记录 |
| GET | `/miniapp/teacher/course/schedule/{id}/edit` | 本人排课编辑资料 |
| POST | `/miniapp/teacher/course/schedule` | 新增本人一对一课程 |
| PUT | `/miniapp/teacher/course/schedule` | 修改本人排课 |
| DELETE | `/miniapp/teacher/course/schedule/{id}` | 删除无业务引用的本人排课 |
| GET | `/miniapp/teacher/course/profile` | 本人的后台授课学科与教师等级 |
| GET | `/miniapp/teacher/course/single/transactions` | 本人的一对一报名及取消申请 |
| POST | `/miniapp/teacher/course/single/{id}/decision` | 确认、拒绝报名或处理取消申请 |
| GET | `/miniapp/teacher/course/single/{id}/history` | 本人报名记录的处理历史 |

时间使用 `HH:mm:ss`；开课、结课日期使用 `yyyy-MM-dd`。每周规则为 `WEEKLY`（明确的周一至周日），暑期规则为 `DAILY_5_1`（上五天休一天）。教师身份由后端固定，不能传其他教师账号；报名人数由报名业务维护。排课编码新增自动生成，修改不可变更。

有签到历史时不得直接改写授课时间、日期、教师、教室或授课形式。有按日期报名的一对一还禁止通过普通调课改变对应日期、地点与重复规则，以保留原始记录。有报名、考勤、调课或作业引用的排课不能删除，可停用并保留历史。

## 一对一协作分工

| 负责人 | 工作 |
| --- | --- |
| 本功能分支 | 排课管理、一对一报名、费用统计 |
| 其他同学 | 开放时段、学员约课、课包记次与扣次、付款 |

本轮没有实现支付、扣课或新增课包表。后续报名与费用统计应对接队友的实际预约、课包和支付数据；未提供金额时显示“暂未提供”，不能把缺失金额当作零元。

`classMode=2` 表示一对一授课形式，不表示已付款或已扣课。本轮在现有课程和报名表内支持教师发布、家长选择具体日期报名与教师处理。未排课程和未经核验的空白区域不能用于承诺可预约。后续预约或课包写入方应复用这里的日期名额与并发规则。

## 验证与启动

后端编译、11 项排课回归、4 组一对一状态回归及微信 WXML 模板编译通过；状态回归使用模拟依赖。本机 MySQL 一对一增量迁移已完成，原业务行数保留，目标字段、唯一约束、生成列和外键已核验。两个实际教师身份的课表、授课配置和一对一事务查询返回成功，课表 ID 与实际数据库教师归属一致。自由地点与灰黄蓝单块状态、失败重试和账号迟到响应通过前端模拟验证；真实微信页面操作尚待验证。协作环境需各自备份后执行增量迁移并重新构建、启动后端；禁止覆盖运行中的 JAR。

课表请求失败时显示友好提示及重新加载按钮，隐藏课次数和空白网格。只有成功响应才能表示零课次；加载失败不能用于判断空闲时间。系统异常完整记录在后端日志中，接口不返回 SQL、Java 堆栈或本机路径，业务校验和权限响应保持原规则。

本机配置、数据库数据和备份不纳入提交。

## 简化的一对一创建参数

教师小程序 POST 创建仅需 `lessonLocation`、`gradeName`、`courseClassName`、`startDate`、`startTime`、`weeks`（1至52）。后台固定本人教师、一对一类型、授课学科及两小时，按开始日期的星期每周一次，最后课次日期为开始日期加上 `(weeks-1)*7` 天。默认持续一周。暂不支持跨午夜排课，开始时间需早于22:00。

创建页不要求填写课程年份、学期、期次、时段、班型、结束日期或招生状态。上述字段由后端映射到已有 `edu_course_schedule`。为避免原若依网格唯一键把不同开始日期的时段误判为同一格，简化创建的学期定位为“一对一+首课日期”；真实日期冲突仍由共享服务校验。

学科和等级由管理员在原用户管理页配置，教师只读；后端不接受客户端指定学科或等级，不根据历史课程、字典首项或教师姓名猜测。缺少学科配置时不能发布。本轮不实现付款、扣课或费用倍率。

## 数据库复用与单次报名

增量 SQL 为 `RuoYi-Vue-master/sql/20261009_one_to_one_incremental.sql`，先备份再执行。沿用 `edu_course_schedule` 的时间、日期和重复规则，仅补自由地点并允许一对一教室为空；班课仍须绑定真实教室。教师配置扩展 `sys_user`，不能写在单条课程中让教师自行修改。

单次日期、确认人和取消申请扩展原 `edu_enrollment`。新表 `edu_enrollment_event` 只追加操作历史，不另建课程或报名表，也不补造历史日期。班课原唯一约束保留，另以有效报名的课程加日期唯一约束防止一对一重复占位。

家长通过 `/miniapp/parent/single/lessons` 查询具体日期，沿用 `/miniapp/parent/enroll` 并提交 `classDate`。0待确认占名额，1已确认占名额，2已取消、3已拒绝释放该日期名额；不改整系列报名人数或支付状态。取消通过 `/miniapp/parent/enrollment/{id}/cancel-request` 提交，待处理期间保留名额，教师批准后释放。处理历史通过 `/miniapp/parent/enrollment/{id}/history` 查询。

教师课表同一日期只显示一个课程块：灰色无人报名、黄色待确认、蓝色已确认、橙色取消申请待处理、绿色已完成。完成依据为同一报名、排课和日期匹配且有效、已复核的到课记录，不能因时间已过而变绿。取消和拒绝记录保留在课次记录中，恢复可报名日期只显示当前状态，不叠加历史块。教师与家长的归属由后端核验；重复确认、取消和拒绝不能重复产生处理结果。上课开始后或已有出勤记录的一对一暂不支持取消或冲正。班课继续复用原报名和取消流程。

## 家长报名按教师查找

现有家长报名页增加教师姓名搜索，可同时选择多位教师，并按教师展示课程分组。年级、学科与教师条件共同生效；空选表示全部教师，重置清除全部筛选。教师账号ID区分同名教师，未绑定账号的历史班次单独显示。

班课沿用 `/miniapp/parent/schedules`，一对一按 `/miniapp/parent/single/lessons` 返回的具体日期展示，两者共用现有报名页的教师全名、多教师、年级和学科筛选。班课按 `scheduleId` 提交，一对一还须提交 `classDate`。若后续接口改为分页，需要将筛选移至后端，保证查询覆盖全部课程。

教师名称优先读取绑定账号的 `sys_user.user_name`，为空时依次回退到 `nick_name` 和排课保存的 `teacher_name`。当前教师账号用姓名作为账号，昵称常为“姓氏＋老师”；筛选选项、已选教师、分组、课程卡片、报名确认与本人报名保持同一姓名来源。按教师 ID 区分同名教师，不按显示姓名合并账号；未绑定账号的历史课程保留原名称。姓名不完整的账号需由后台维护，界面不补造姓名。

## 教师“我的课程”模块（合并后的当前入口）

用户确认将原“我的课表”与“一对一课程”合并，教师首页仅保留“我的课程”入口。复用已注册的 `pages/teacher-single-transactions` 路由，旧详情链接继续可用；教师从旧 `pages/timetable` 入口进入时跳转到统一模块。家长原课表与报名入口继续沿用原页面。

统一模块包含周课表、课程列表、报名处理、课次记录四个页签。周课表和课程列表默认显示本人班课及一对一，可筛选全部／班课／一对一；隐藏课程时明确提示空白不能视为可预约。周课表沿用 `templates/teacher-week-calendar.wxml`，左侧时间轴固定，星期标题与课程同一横向滚动容器，保留全天空档、周切换、日期跳转和待排提示。

课程列表每张卡片对应一条排课，可查看具体日期与学员记录，沿用原编辑页新增一对一、修改本人排课、下架及删除；有业务引用不能删除。班课修改保留原权限限制，教师新增仍限一对一。报名处理沿用原确认、拒绝和取消申请接口；课次记录查看一对一报名处理历史及对应日期的上课记录，班课上课记录复用原学员详情。页面加载失败或身份变化时清除旧数据，显示友好提示，加载失败不能表示课程数量为零。

教师首页“我的课程”图标右上角显示红色待处理数量，模块内的待处理统计和报名处理页签同步提醒。数量为待确认报名及待处理取消申请，一条报名即使同时有两种状态也只计一次；归零隐藏，超过99显示99+。计数不是未读消息，打开页面不会清零，成功处理后重新查询；已取消、已拒绝及不能继续处理的历史不计入。

首页和模块通过同一 `/miniapp/teacher/course/single/transactions` 接口及 `utils/teacher-course-state.js` 统一计数。新增响应属性 `canProcess` 由后端按上海时间、报名有效状态和既有上课历史限制计算，不新增数据库字段；动作接口仍在事务内复核权限与状态。前台每30秒刷新，隐藏／退出后停止，切角色或教师身份后丢弃旧响应。数量查询失败显示未知和重试，不显示假零；模块后台刷新保留当前课表、筛选和详情，失败时明确旧数据并暂停处理。

家长一对一列表按排课 ID 折叠成课程卡片，展开后选择具体日期。例如持续四周的一门课程含四个课次，不是四门重复课程；提交仍是排课 ID 加所选课次日期。课程与课次数分别显示，保留日期独立名额和状态规则。

本轮后端构建、页面语法、实际 WXML 编译及前端模拟验证通过。实际教师接口与数据库归属一致，其他教师不能读取本人课程编辑资料；家长班课、一对一、报名与课表接口的姓名来源已核验。没有创建测试课程或报名。微信开发者工具的实际界面点击仍需核验；付款及课包扣次继续等待对接。

合并后已核验角标、处理减数、归零及99+、后台刷新保留详情、失败重试、身份迟到响应及隐藏定时器清理；原11项排课及4组一对一回归通过。后端已重新构建启动，真实教师待处理数量与当前数据库一致，家长原接口返回正常。计数和可处理属性仅查询派生，本次合并不要求新的数据库迁移。

## 接收代码与数据库更新

本次交接分支为团队仓库 `shengyinHHU/MingYuan` 的 `codex/my-courses-one-to-one`，基于老师已合并的团队主分支。代码、测试与增量 SQL 一同交接；开发者个人工程配置、数据库数据和整库备份不在本次提交中。

### 拉取功能分支

先保存接收者自己的未提交改动。在其远端名为 `upstream` 且指向团队仓库时执行：

```bash
git fetch upstream
git switch --track upstream/codex/my-courses-one-to-one
```

若该分支已在本机存在，切换到该分支后使用 `git pull --ff-only`；若远端名为 `origin`，将上述 `upstream` 替换为 `origin`。

### 数据库迁移顺序

1. 使用团队项目已有数据库基线，确认数据库为 MySQL 8.0；先停止对应后端并备份本机库。本功能不提供整库覆盖脚本。
2. 团队财务代码需要 `edu_course_schedule.unit_price` 和 `edu_finance_expense`。若尚未具备，核对后执行团队主分支已有的 `database/migrations/20261007_finance_dashboard.sql`；已有则跳过。
3. 核对一对一字段、索引和历史表。如果尚未执行本功能迁移，再执行 `RuoYi-Vue-master/sql/20261009_one_to_one_incremental.sql`。此脚本不是可重复执行脚本；若字段、索引或历史表已存在，先确认是否已完整迁移，部分迁移不能直接重跑。

在仓库根目录执行以下命令，按提示输入接收者自己的密码；`root` 和数据库名按其环境调整：

```bash
mysql --default-character-set=utf8mb4 -u root -p mingyuaneduminiapp --execute="source RuoYi-Vue-master/sql/20261009_one_to_one_incremental.sql"
```

一对一迁移涉及 `sys_user` 的授课学科与等级、`edu_course_schedule` 的自由地点及可空教室、`edu_enrollment` 的具体日期与处理记录，以及追加历史表 `edu_enrollment_event`。原报名唯一键由兼容旧报名的唯一键替代，另增加按课程和日期占位的唯一键；不补写旧报名日期，不导入学生、报名或支付数据。执行后需核验字段、生成列、唯一键和外键，并确认原业务记录没有减少。

仓库外的本机备份和本机自动迁移工具不属于交接包，不依赖任何开发者固定的磁盘路径。

### 构建与配置

- 后端在 `RuoYi-Vue-master` 构建，先停止旧进程，再执行 `mvn -pl ruoyi-admin -am package -DskipTests`，使用接收者自己的 MySQL、Redis和环境配置启动；不要覆盖正在运行的 JAR。
- 若依前端在 `RuoYi-Vue-master/ruoyi-ui` 安装项目依赖后运行 `npm run dev`；小程序导入 `WeChatMiniApp`，后端地址与工程配置按接收者本机环境设置。
- 教师学科和等级由若依原用户管理页维护；缺少授课学科时不允许创建一对一课程。教师选择免密登录仅用于已启用 `local` profile 的开发环境。
- 重点核验本人班课及一对一课表、教师间隔离、具体日期报名、确认／拒绝、取消申请与历史、红色待处理数量和家长教师筛选。付款与课包扣课由其他同学负责，接手时继续复用已有接口。
